# 2. 리포트 간 모순 — 판정과 근거

8개 리포트를 대조하니 6개 지점에서 정반대 결론이 나왔습니다. 하나씩 판정합니다.

## 모순 1. 영상 길이 — 30~60초 vs 1~3분

**판정: 30~60초. 확실.**

공식 모달 원문을 직접 재확인했습니다. 두 곳에 중복 기재되어 있습니다.

- 제출물 표: `2 | 플레이 동영상 | 30~60초 플레이 영상 | YouTube (링크)`
- 항목별 상세: "30~60초 분량으로, 실제 게임 플레이 장면을 중심으로 제작해 주세요."

'1~3분'의 출처를 저장소에서 grep으로 추적한 결과 두 파일뿐이고, 두 파일 모두 URL이 0개입니다.

```
docs/research/agy_research/hackathon_analysis.md:24  "1~3분 분량의 게임플레이 핵심 재미와..."
```

## 모순 2. 퍼즐 — "퍼즐로 가라" vs "순수 퍼즐 절대 금지"

**판정: 퍼즐 라벨은 허용. 단 두 조건이 붙는다.**
**(a) 퍼즐 플랫포머 형식 금지 (b) 핵심 동사가 기존 퍼즐 관습과 달라야 함**

두 리포트는 **서로 다른 것을 측정**했습니다.

| | 포화 리포트 | 한국 심사 리포트 |
|---|---|---|
| 측정 대상 | 20,282편 중 **소비자에게 발견될 확률** | 전문가가 **반드시 열어보는 심사** 결과 |
| 데이터 | 퍼즐 14/4,022 = 0.34%, 2D 플랫포머 3/1,658 = 0.18% | BIC 2025 상위 4상 중 3개 퍼즐, 인디크래프트 2025 최우수상 퍼즐 |
| 우리 상황 적용성 | **적용 안 됨** | **적용됨** |

근거:

1. **NAN 사전심사에는 발견 가능성 문제가 구조적으로 존재하지 않습니다.** 심사자가 링크를 반드시 엽니다. Steam 0.34%는 "노출을 못 받아서 죽는" 확률이지 "품질이 낮아서 죽는" 확률이 아닙니다.
2. **포화 리포트 스스로 §0에서 인정했습니다**: "Steam에서 잘 팔린다 ≠ 심사자가 신선하다고 느낀다."
3. **포화 리포트가 실제로 금지한 것은 '퍼즐 플랫포머'와 '장르 관습 재현형 퍼즐'입니다.** GMTK 주최자 Mark Brown이 "밈"이라 부른 것은 정확히 "작은 캐릭터를 움직여 상자 밀고 버튼 누르는 것"이고, top100 중 약 20개가 그것이었습니다. itch.io `puzzle-platformer` 태그는 15,633개입니다.
4. 반대로 게임잼 우승작·IGF Nuovo 수상작 중 퍼즐 계열은 전부 **핵심 동사가 새롭습니다**: Baba Is You(규칙 문장을 민다), Understand(규칙을 특정한다), 0PLAYER(정지 이미지 1장), Is This Seat Taken?(좌석 배치 CSP), Strange Jigsaws(지시문이 조각).
5. NHN 2026 신작 6종 중 2종이 퍼즐(최애의 아이 Puzzle Star, 도검난무 파즈기리)입니다. 심사위원이 퍼즐 규칙 설계를 **자기 실무로 평가할 수 있는 언어**를 갖고 있습니다.

## 모순 3. "5종 균등" vs "한 축 극단화"

**판정: 모순이 아니라 층위가 다르다. 제출물 5종은 이진 관문, 게임의 매력은 극단화 대상.**

- 공식 원문은 **"하나라도 누락 시 심사 대상에서 제외"** 입니다. 누락은 감점이 아니라 **심사 자체 미실시**입니다. 즉 5종은 점수 축이 아니라 게이트입니다.
- 게임잼 리포트가 말한 "한 축 극단"은 **평가 항목 간 균형**에 관한 것입니다. GMTK 2025는 종합 순위를 폐지하고 단독 선정으로 바꿨는데, 20픽 중 15개가 어떤 항목에서 500위 밖이었고 최악 항목 등수 중앙값이 1,153위였습니다(Goop Snake: Narrative 1,897위 / SongRunner: Artwork 3,086위). 동시에 20개 중 14개가 최소 한 항목 20위 이내였습니다.
- 반대로 크라우드 평균 방식(Brackeys 2025.2, 2,272편)에서는 Top10의 최악 항목 등수가 55~245위로 약점이 없었습니다.

**NAN은 소수 심사위원이 10팀을 고르는 구조이므로 GMTK 2025형입니다.**

→ 통합 규칙:

## 모순 5. 기술 스택 — 바닐라 Canvas vs Phaser

**판정: 바닐라 TypeScript + Canvas 2D 단일 추천. Phaser는 배제.**

결정적 근거를 직접 재확인했습니다.

1. **npm `phaser` dist-tag `latest` = 4.2.1** (2026-07-28 조회). 에이전트가 `npm install phaser`를 치면 v4가 들어옵니다.
2. **Phaser 공식 문서: "Math.TAU (now correctly PI × 2)"** — v3에서는 PI/2였습니다. **이름은 그대로인 채 값만 바뀌었습니다.** 예외도 콘솔 에러도 없이 각도만 조용히 틀어집니다. 에이전트는 절대 못 잡고 사람이 눈으로 보고 원인부터 찾아야 합니다.
3. Phaser 공식은 "Every major model already knows the Phaser API well"이라 주장하지만 **벤더 자체 주장이고 독립 검증 수치가 없습니다.** 반대로 서드파티 Claude Code 플러그인 `phaser4-gamedev`는 제작 이유를 "AI models lack deep knowledge of Phaser 4's API, leading to incorrect code generation"이라 적고, **폐기된 v3 API를 저장 전에 차단하는 PreToolUse 훅**을 넣었습니다. 훅으로 막아야 할 만큼 모델의 기본 출력이 v3라는 뜻입니다.

**Canvas 2D API(`CanvasRenderingContext2D`, `requestAnimationFrame`, `AudioContext`)는 십수 년간 바뀌지 않았고 버전 모호성이 구조적으로 0입니다.** 이것이 이번 조건에서 가장 큰 단일 장점입니다.

출처: [registry.npmjs.org/phaser](https://registry.npmjs.org/phaser) · [Phaser 3 vs Phaser 4](https://phaser.io/news/2026/05/phaser-3-vs-phaser-4) · [Yakoub-ai/phaser4-gamedev](https://github.com/Yakoub-ai/phaser4-gamedev)

## 모순 6. 제출 타이밍 — "마감 직전" vs "조기"

**판정: 둘 다 NAN에 적용되지 않는다. 실제 제약은 다른 곳에 있다.**

- 게임잼 리포트: 우승작 제출 시각 중앙값이 마감 1시간 27분 전
- 30초 영상 리포트: "평가 대부분은 평가 기간 시작 직후에 몰린다" → 조기 제출

두 주장 모두 **itch.io처럼 평가 기간 중 계속 제출이 들어오고 평가자가 무작위로 게임을 고르는 구조**를 전제합니다. NAN은 8/10 일괄 마감 후 8/22까지 12일간 심사합니다. 제출 순서가 심사 노출에 영향을 주지 않습니다.

**실제 제약 두 개:**
- "접수 마감 후에는 제출 내용을 변경할 수 없습니다" → 마감 직전 제출은 **수정 기회 0**
- "심사 종료 시점까지 접근 가능한 상태로 유지" → 8/10~8/22 사이 링크가 한 번이라도 죽으면 심사 불가

→ **조기 제출의 이점은 순서가 아니라 링크 검증 시간 확보입니다.** 8/08~8/09를 예비일로 두되 **이 기간에 기능을 넣지 않고** 로그아웃 링크 확인·시크릿 창 실행·저장소 공개 여부·YouTube 공개 상태만 반복 검증합니다.

## S1 보강 — AI 활용 기술 문서에 넣을 증거물 (강한 순)

문서가 아니라 **저장소에 실제로 존재하는 파일**이 가장 강한 증거입니다. 위조가 어렵고 심사자가 3분 만에 스캔할 수 있습니다.

| 증거물 | 증명하는 것 |
|---|---|
| `CLAUDE.md` (20줄 이내) | 프로젝트 계약(상태 변경 단일 경로, 순수 함수 규칙, 금지 사항)을 **사람이 설계**했다 |
| `.claude/agents/*.md` | 역할 분업이 말이 아니라 파일로 존재한다 |
| `.claude/settings.json`의 Stop 훅 | 검증 통과 전 턴 종료를 **차단**했다 |
| `features.json` | 기능 목록·검증 방법·상태를 기계가 읽는 형식(JSON)으로 관리했다 |
| `scripts/balance-sim.ts` | 밸런스를 감이 아니라 **수치로 판정**했다 |
| `NOTES.md` / `progress.md` | 컨텍스트 리셋을 넘어 상태를 인계했다 |
| 커밋 로그 | 시각·주체·검증이 한 줄에 들어간 형태 |

**폐기한 프롬프트 3개와 폐기 사유**를 반드시 넣습니다. 성공 프롬프트만 나열하면 홍보문으로 읽히고, 정우진 대표가 말한 "**판단하고 선택하는 인간의 역량과 주관**"에 정확히 대응하는 것은 폐기 판단 쪽입니다.

**시간 단축 수치는 체감이 아니라 커밋 타임스탬프 실측으로 씁니다.** METR 무작위 대조 시험(숙련 개발자 16명, 이슈 246건)에서 개발자들은 20% 빨라졌다고 체감했으나 실측은 **19% 느려졌습니다**. 체감과 실측이 39%p 어긋납니다. 실측치를 쓰는 것 자체가 문서의 신뢰도를 만듭니다.

# 6. 최종 추천 기술 스택 — 1개

```
언어      TypeScript (strict)
렌더      HTML5 Canvas 2D — 게임 프레임워크 없음
          (ctx.drawImage / fillRect / requestAnimationFrame)
오디오    Web Audio API 절차 생성 (외부 오디오 파일 0개)
빌드      Vite  ← base: '/<REPO>/' 필수
배포      GitHub Actions → GitHub Pages
검증      Playwright MCP + Chrome DevTools MCP
          (스모크 → 밸런스 수치 → 시각 회귀 3단)
외부 의존 없음. 부득이 추가 시 캐럿 없이 정확 핀
```

## 왜 이것 하나인가

| 축 | 근거 |
|---|---|
| **LLM 정확도** | Canvas 2D API는 십수 년간 불변. **버전 모호성이 구조적으로 0**. Phaser는 npm latest가 4.2.1이고 `Math.TAU`가 이름 그대로 값만 PI/2→PI×2로 바뀌어 **조용한 각도 버그**를 만듦 |
| **GH Pages 즉시 실행** | 빌드 없이도 가능. Godot은 단일 스레드 강제, Unity는 100MB 벽 |
| **GUI 불필요** | 전 산출물이 텍스트 소스. Unity/Unreal은 에디터 필수 = 전제 붕괴 |
| **에이전트 자율 루프** | 브라우저 게임만 "실행 → 스크린샷 → 수치 추출 → 수정" 루프가 닫힘. 우리 환경에 playwright/chrome-devtools MCP가 **이미 붙어 있어 추가 설정 0** |
| **사례 근거** | MVP 플레이 가능까지 **9분 11초**(1,748줄, 단일 파일), 하루에 브라우저 게임 3개(총 1,950줄) 등 실측 다수 |
| **S1 부수 효과** | 게임 루프·충돌·파티클·오디오 합성까지 에이전트가 전부 작성한 기록이 커밋에 남음. "프레임워크 컴포넌트를 조립했다"보다 **검증 가능한 AI 활용 증거** |

## 1일차에 반드시 세울 것 (게임 코드보다 먼저)

1. **배포 파이프라인 먼저.** GitHub Actions → Pages를 뚫어 심사 링크를 1일차부터 살려둡니다. 커스텀 Actions 워크플로면 **시간당 10회 빌드 제한이 적용되지 않으므로**(GitHub 공식 확인) 매 커밋 자동 배포가 가능합니다.
2. **`base: '/<REPO>/'` 설정.** 이것을 빠뜨리면 하위 경로 배포에서 흰 화면이 뜹니다. 가장 흔한 실수입니다.
3. **고정 타임스텝 + 결정론적 시드.** 같은 입력에 같은 결과가 나와야 검증 루프가 성립합니다.
4. **`window.__game` 상태 노출.** Playwright가 읽을 수 있는 형태로 스코어·경과 시간·이벤트 카운트를 노출합니다.
5. **`scripts/balance-sim.ts`.** 헤드리스 60초 자동 플레이 → JSON 리포트 → 허용 범위 위반 시 실패. Stop 훅이 강제합니다.

이것이 필요한 이유는 AI 에이전트 개발의 최악 실패 모드가 버그가 아니라 **"테스트 초록불 + 게임 플레이 불가"** 이기 때문입니다. 실측 증상은 60초 동안 누적 데미지 0, 재미 구간이 10~30초여야 하는데 레벨업이 3.9초마다 발생하는 식입니다. JAMER 벤치마크도 에이전트가 컴파일 통과율은 77.3%→82.7%로 올렸으나 런타임 행동 품질은 "no gains"였고, 결론은 "**the bottleneck lies in architectural design rather than syntactic correctness**"였습니다.

# 8. 1등 조건 — 한 문단 정의

> **NAN 2026 사전심사 1등은 "가장 잘 만든 게임"이 아니라 "심사자가 30초 안에 처음 보는 규칙 하나를 이해하고, 저장소를 열었을 때 그 규칙이 어떻게 지휘되어 나왔는지가 파일로 증명되는 제출물"이다.** 제출물 4종은 점수 축이 아니라 이진 관문이므로 체크리스트로 100% 채우고 여기에 창의성을 쓰지 않는다. 실제 변별은 두 축에서만 나며, 그 둘은 매체가 다르다 — 영상은 **AI를 한 번도 언급하지 않고** 게임의 배반 하나만 보여주고, AI 활용 기술 문서는 **게임을 자랑하지 않고** 무엇을 버렸고 왜 버렸는지, 어떤 자동 검증이 무엇을 잡아냈는지만 쓴다. 심사위원은 7월 1일부터 전사적으로 클로드를 쓰고 있고 Steam 신작의 30.8%가 이미 AI를 공시하므로 "AI로 만들었다"는 사실에는 정보량이 0이며, 유일하게 새로운 정보는 **"어디까지 자동화했고 어디서 사람이 개입했으며 왜 그 지점이었는가"의 해상도**다. 그리고 이 대회는 상금 8,000만 원에 근속 보너스 3,000만 원 × 9명을 얹어 3.5억을 잡았고 부정행위 시 "인재 풀 등록 제외"를 명시하므로, 심사는 게임 선발이 아니라 **채용 선발**이다. 따라서 커밋 메시지 한 줄, `CLAUDE.md` 20줄, `balance-sim.ts` 하나가 게임의 재미와 같은 무게를 가진다. 마지막으로, 이 모든 것이 **9단어 이내의 한 문장**으로 설명되지 않으면 어느 것도 전달되지 않는다.
