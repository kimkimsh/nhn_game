# 최종 5개 스코어카드와 CEO 리뷰

## 1. 평가식

사용자의 요청에 따라 개발 리소스와 구현 난이도는 점수에서 제외했다.

| 항목 | 배점 | 질문 |
|---|---:|---|
| 핵심 동사의 새로움 | 25 | 설정을 지워도 반복 행동이 새롭게 들리는가 |
| 순간 재미와 손맛 | 25 | 첫 입력부터 내가 원인이고 결과가 시원한가 |
| 영상 전달력 | 20 | 무자막 10초에 원인과 결과가 보이는가 |
| 한 규칙의 확장성 | 15 | 적·보스·피날레가 같은 규칙으로 커지는가 |
| 실패의 재미 | 10 | 실패가 새 장면과 재도전 욕구를 만드는가 |
| 기존안과 분리도 | 5 | 기존 35개와 독립된 핵심 상태를 갖는가 |

## 3. Office Hours 전제 반박

### 전제 1: 더 참신하면 더 재밌다

거짓이다. 실뜨기, 설정 메뉴, 기억하는 난수기처럼 새로워도 손이 심심하거나 설명이 길면 탈락시켰다.

### 전제 2: 30초 영상이 강하려면 폭발적 액션이어야 한다

과장이다. 조용한 퍼즐도 명료한 변화와 강한 호기심이 있으면 통한다. 필요한 것은 이펙트 양이 아니라 `입력 → 변화 → 새 위험`의 가독성이다.

### 전제 3: 선행작이 전혀 없어야 독창적이다

현실적이지 않다. 이번 조사에서도 CLEAN 후보는 없었다. 원전과 인접작을 먼저 인정하고 조합과 반복 동사의 차이를 증명하는 편이 더 강하다.

### 전제 4: AI 에이전트를 많이 쓰면 결과물이 자동으로 좋아진다

거짓이다. AI는 후보 수와 검증 폭을 늘리지만, 손맛과 취향의 최종 판단을 대신하지 못한다. `무엇을 버렸는가`가 AI 지휘 역량의 핵심 증거다.

### 전제 5: 1등할 주제를 문서만으로 확정할 수 있다

불가능하다. 문서는 약한 후보를 제거할 수 있을 뿐이다. 상위 2개는 10초 무자막 프로토타입에서 실제 손맛을 비교해야 한다.

## 4. 10스타 버전

### 깔고 앉는 용사

단순 포획 게임이 아니라, 플레이가 진행될수록 화면 중앙에 `내가 만든 살아 있는 생태 탑`이 자란다. 탑의 층마다 적의 표정과 행동이 계속 보이고, 이동할 때마다 서로 싸우며, 무너지는 순간 전투 전체가 다시 풀린다. 마지막에는 보스 부위까지 층으로 빼앗아 보스 자신의 기술 순서를 재조립한다.

### 반띵 대왕

단순 절단 퍼즐이 아니라, 적의 욕망을 이용해 무기와 지형을 즉석 설계하는 결투다. 보스가 삼킨 큰 조각도 사라지지 않고 몸 안에서 계속 작동한다. 피날레에서는 지금까지 삼킨 모든 절반이 보스 내부에서 하나의 재앙 기계로 조립된다.

### 시선 도둑

단순 시야 스텔스가 아니라 `관객이 기억한 공연`과 `실제로 일어난 범행`이라는 두 현실을 동시에 연출한다. 엔딩 리플레이에서 같은 30초가 전혀 다른 두 영상으로 재생되고, 플레이어는 자신이 만든 거짓 기억의 완성도를 본다.

### 심장 공기놀이

단순 저글링이나 귀환 심장 무기가 아니라 몸과 심장 두 주인공이 번갈아 싸우는 공중 안무다. 숙련자는 더 많은 표식을 쌓기 위해 캐치를 늦추되, 불안정해지는 심장을 결국 몸으로 직접 받아야 피해를 확정한다. 놓치면 표식 전체가 사라지고 추격전으로 뒤집힌다.

### 반대편은 보스

단순 로프 플랫폼이 아니라 경기장 전체가 하나의 거대 저울이 된다. 적, 건물, 플레이어, 보스, 달이 같은 질량 네트워크에 들어가고, 한쪽의 승리가 반드시 다른 쪽의 추락을 만든다.

## 5. CEO 11개 관점 리뷰

### Section 1. Architecture Review — 재미 구조

다섯 게임은 모두 하나의 핵심 상태를 중심으로 순수하게 분리된다.

```text
플레이어 입력
    │
    ▼
핵심 관계 생성
덮임 / 분할 / 주의 / 공중 심장 / 반대추
    │
    ▼
즉시 보상
포획 / 남은 무기 / 은폐 / 행동 해방 / 이동
    │
    ▼
같은 관계가 만든 새 위험
불안정 / 상대 선취 / 의심 / 추락 / 상반 운동
    └──────────────────────────────► 다음 입력
```

일반 공격, 별도 제작 메뉴, 별도 최종 미니게임을 추가하면 구조가 무너진다.

### Section 2. Error & Rescue Map — 기획 실패

| 실패 | 발생 조건 | 사용자 경험 | 구조적 구제 |
|---|---|---|---|
| 판정 불신 | 덮임·절단·시선 결과가 예상과 다름 | 억울함 | 실행 전 예상 결과를 형태로 표시 |
| 관람형 전락 | 입력 뒤 결과를 오래 기다림 | 손이 심심함 | 결과 전에 자세·위치·해제 개입 창 제공 |
| 예외 규칙 폭증 | 적마다 새 법칙 | 암기 피로 | 적은 같은 규칙의 물성만 변경 |
| 혼돈 | 연쇄 원인이 가려짐 | 랜덤처럼 보임 | 궤적·단면·층·줄을 파티클보다 우선 |
| 한 번 웃고 끝 | 첫 반전 뒤 판단 반복 | 아이디어 데모 | 누적 상태가 다음 입력을 어렵게 함 |
| 피날레 단절 | 최종전에서 새 조작 | 기믹 모음 | 첫 규칙의 규모만 확대 |

### Section 3. Security & Threat Model — 권리와 오프라인

- 계정, 서버, 외부 API, 사용자 생성 콘텐츠가 필요 없다.
- 외부 에셋과 오픈소스는 출처·라이선스를 기록해야 한다.
- 실제 플레이와 제출 영상이 같아야 한다.
- 선행작 부재를 세계 최초로 홍보하지 않는다.
- 가장 가까운 원전과 게임을 AI 활용 문서에 먼저 인용한다.

### Section 4. Data Flow & Interaction Edge Cases — 입력

```text
입력
 ├─ 유효 대상 없음 ──► 상태 변화 없이 명확한 실패 피드백
 ├─ 대상 둘 겹침 ────► 선택 우선순위를 미리 표시
 └─ 유효 대상
       │
       ▼
   예상 결과 표시
       │
       ├─ 취소 ──────► 원상태
       └─ 확정
           │
           ▼
      관계 생성 → 결과 → 새 위험 → 다음 입력 가능
```

필수 예외는 화면 밖 대상, 동시에 두 결과, 보스 무적 구간, 상태 전환 중 입력, 재시작 직전 잔류 물리다.

### Section 5. Code Quality Review — 규칙 순도

코드 구현 전에도 다음 구조 원칙을 잠근다.

- 핵심 관계 판정은 한 책임의 시스템으로 둔다.
- 적은 판정 코드를 복제하지 않고 속성 데이터만 제공한다.
- 연출은 판정 결과를 구독하며 규칙을 바꾸지 않는다.
- 결과 재현을 위해 동일 입력과 초기 상태는 같은 판정을 내야 한다.
- 기존 AGENTS.md의 클래스 분리·상수 분리·명명·중괄호 규칙을 구현 단계에서 적용한다.

### Section 6. Test Review — 재미 테스트

| 테스트 | 합격 기준 |
|---|---|
| 3초 무자막 | 만질 대상과 첫 결과를 가리킬 수 있음 |
| 10초 욕구 | 규칙 설명 전에도 직접 해보고 싶다는 반응 |
| 3회 입력 | 같은 입력이 상태 때문에 다른 판단을 만듦 |
| 실패 재미 | 실패 직후 원인을 말하고 바로 재시도 |
| 무음 영상 | 원인·위험·결과를 설명 가능 |
| 제목 회상 | 제목과 행동을 함께 기억 |
| 적대적 비교 | 인접작과 차이를 동사로 말함 |

### Section 7. Performance Review — 인지 성능

개발 비용은 점수에서 제외했지만 인지 성능은 재미다.

- 핵심 관계가 화면 밖으로 나가지 않는다.
- 파티클이 층, 절단면, 눈동자, 심장, 줄을 가리지 않는다.
- 큰 연쇄 전 짧은 예고를 둔다.
- 결과 순간만 시간 압축을 사용한다.
- 화면에 보이는 물체 수보다 원인 추적 가능성을 우선한다.

### Section 8. Observability & Debuggability Review

선정 후 구현할 때 필요한 디버그 관찰 항목이다.

- 현재 덮임 비율과 층 질량 중심
- 절단 양쪽의 가치 계산
- 객석 집단과 특수 관객의 주의 대상·전환 이유
- 심장 예상 궤적과 상태 전환
- 도르래 양쪽 질량·장력·운동량
- 실패 직전 3초 입력과 결과 재생

### Section 9. Deployment & Rollout Review — 제출 경험

```text
실제 게임
 ├─ 브라우저 완주 검증
 ├─ 첫 10초 대표 장면
 ├─ 30~60초 실제 플레이 영상
 ├─ 게임 소개 PDF
 └─ 프롬프트·폐기 로그·출처를 포함한 AI 활용 PDF
```

영상용으로만 존재하는 장면을 만들지 않는다. 실제 첫 플레이에서도 같은 핵심 장면이 나와야 한다.

### Section 10. Long-Term Trajectory Review

새 시스템을 붙이지 않고 확장할 축이 있는지 확인했다.

- 깔고 앉는 용사: 층 순서와 층 사이 상호작용
- 반띵 대왕: 가치 기준과 복합 재료
- 시선 도둑: 관객 성향과 기억의 차이
- 심장 공기놀이: 반사 관계와 캐치 위험
- 반대편은 보스: 질량 네트워크와 연결 타이밍

모두 주제 선정 단계에서 되돌리기 쉬운 선택이다. 실제 프로토타입 전 가역성은 5/5다.

### Section 11. Design & UX Review

| 주제 | 첫 번째로 보여야 할 것 | 두 번째 | 세 번째 |
|---|---|---|---|
| 깔고 앉는 용사 | 예상 덮임 | 새 층 | 스택 흔들림 |
| 반띵 대왕 | 절단선 | 보스 선택 기준 | 남은 조각 기능 |
| 시선 도둑 | 객석 눈동자 | 보여주는 손 | 숨기는 행동 |
| 심장 공기놀이 | 심장 궤적 | 낙하 지점 | 몸의 귀환 경로 |
| 반대편은 보스 | 연결선 | 양쪽 질량 | 반대 운동 |

색만으로 상태를 구분하지 않는다. 형태, 위치, 운동, 선 패턴을 함께 쓴다.

## 9. Dream state delta

현재 문서가 주는 것은 `무엇을 만들지`에 대한 강한 선택지와 폐기 기준이다. 아직 없는 것은 실제 손맛 증거다.

## 10. 최종 CEO 판단

### 1순위: 깔고 앉는 용사

순수 재미를 최우선으로 할 때 가장 강하다. 조준과 착지의 손맛, 누적 성장, 불안정성, 실패 코미디가 모두 첫 규칙에서 나온다. 포획한 적이 사라지지 않고 화면에 층으로 남아 플레이의 역사가 보이는 점도 영상에 유리하다.

### 2순위: 반띵 대왕

가장 참신한 한 문장과 가장 큰 피날레를 갖는다. 다만 보스의 선택과 남은 조각의 사용이 실제로 빠르게 이어지지 않으면 정적인 절단 퍼즐이 될 위험이 있다.

### 선택 직후 해야 할 일

상위 두 안을 회색 원·사각형만으로 각각 10초짜리로 만든다.

- `깔고 앉는 용사`: 발사 → 완전 덮기 → 3층 → 붕괴
- `반띵 대왕`: 절단 → 보스 선취 → 남은 조각 휘두르기 → 내부 폭발

다섯 명에게 설명 없이 보여주고 `어느 쪽을 지금 직접 해보고 싶은가`만 묻는다. 4:1 이상이면 그 안을 고르고, 3:2면 손맛이 더 강한 쪽을 한 번 더 비교한다.

문서만으로는 여기까지가 정직한 최대 확신이다.
