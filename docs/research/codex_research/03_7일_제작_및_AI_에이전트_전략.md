# 7일 제작 및 AI 에이전트 전략

## 플랫폼 결론

**Phaser 3.90 + TypeScript + Vite + GitHub Pages**를 기본 스택으로 권장한다.

- Phaser 3.90은 Scene, 입력, 오디오, Arcade Physics를 갖춘 성숙한 계열이다.
- TypeScript는 여러 AI 에이전트가 동시에 작업할 때 계약과 상태 오류를 줄이는 데 유리하다.
- Vite와 GitHub Pages는 정적 번들 배포가 단순하다.
- 모든 라이브러리와 에셋을 번들에 포함하면 게임 플레이 자체는 외부 API 없이 동작한다.

근거: [Phaser 3.90 릴리스](https://phaser.io/download/release/v3.90.0), [Phaser 공식 프로젝트 생성기](https://phaser.io/tutorials/create-game-app), [Vite 정적 배포](https://vite.dev/guide/static-deploy.html), [GitHub Pages 소개](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

관제처럼 물리가 전혀 없는 결정론적 게임은 PixiJS 8도 적합하다. 다만 PixiJS는 렌더러 중심이라 장면·충돌·상태 구조를 더 직접 만들어야 한다. [PixiJS 렌더러 가이드](https://pixijs.com/8.x/guides/components/renderers), [PixiJS 이벤트 가이드](https://pixijs.com/8.x/guides/components/events)

Godot 경험이 이미 충분하다면 GDScript 기반 2D 웹 빌드도 가능하다. 그러나 Godot 4의 C# 프로젝트는 웹 내보내기를 지원하지 않고, 브라우저는 WebAssembly·WebGL2와 배포 설정의 영향을 받는다. 일주일 과제에서는 새로운 엔진을 배우기 위한 선택으로 권하지 않는다. [Godot 웹 내보내기 공식 문서](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)

## 강제 스코프 상한

- 핵심 시스템 5개 이하
- 한 화면 또는 퍼즐 4~5개 이하
- 적 2종 이하, 보스 없음
- 고유 그래픽 모듈 12개 이하
- BGM 1곡, 효과음 6~10개
- 이동 외 액션 버튼 1개
- 네트워크, 계정, 서버 저장, 런타임 외부 API 없음
- 레벨 에디터, 분기 서사, 업그레이드 트리 없음

## 브라우저 함정

- 브라우저는 사용자 입력 전 자동 오디오 재생을 막을 수 있으므로 `게임 시작` 클릭 후 오디오 컨텍스트를 시작한다. [MDN Autoplay 가이드](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)
- 탭이 비활성화되면 게임을 자동 일시정지하고 복귀 시 카운트다운을 제공한다.
- 새로고침과 URL 직접 접근에서 상대 경로 에셋이 깨지지 않게 Vite `base`를 확인한다.
- 포인터 캡처나 전체 화면은 필수 조작으로 만들지 않는다.
- 오디오 정보는 색·파동·아이콘으로도 제공한다.

## AI 에이전트 운용

### 역할 분리

- 디렉터 에이전트: 범위와 인터페이스 계약 관리
- 구현 에이전트: 한 번에 한 시스템만 수정
- 테스트 에이전트: 규칙 단위 테스트와 브라우저 재현 절차 작성
- 리뷰 에이전트: 상태 전이, 에셋 경로, 상수, 라이선스 검토
- 인간 디렉터: 모든 통합 커밋을 직접 플레이하고 승인

### 병렬 작업 원칙

- 같은 파일을 동시에 수정하지 않는다.
- 입력, 규칙, 렌더링, 오디오를 작은 모듈로 분리한다.
- 에이전트마다 완료 조건과 금지 범위를 적는다.
- 큰 기능 요청 대신 테스트 가능한 수직 조각을 요청한다.
- 생성 코드는 빌드 성공이 아니라 실제 플레이 승인 후 병합한다.

### AI 활용 기록 형식

| 날짜 | 도구·모델 | 목적 | 핵심 지시 | 결과 | 인간의 채택·수정·폐기 | 관련 커밋 |
|---|---|---|---|---|---|---|
| 예시 | Codex | 분기기 상태 머신 | 결정론적 전환과 테스트 작성 | 초안 생성 | 경계 조건 수정 후 채택 | 해시 |

추가로 에셋마다 `파일 / 제작 방식 / 원본 URL / 라이선스 / 수정 내역`을 남긴다.

## 완료 정의

- 첫 화면에서 10초 안에 조작을 시작할 수 있다.
- 30~60초 영상에 핵심 규칙, 위기, 보상이 모두 나온다.
- 심사자가 설명서 없이 한 판을 끝낼 수 있다.
- 게임의 모든 경로에 재시작이 있다.
- 주요 상태 규칙에 자동 테스트 또는 재현 가능한 수동 테스트가 있다.
- 외부 네트워크가 끊겨도 로드된 게임의 한 판을 끝낼 수 있다.
- AI 활용과 라이선스 문서가 소스·커밋과 일치한다.
