# 「환도(還刀)」 구현 기획안

`docs/spec/기능_명세서.md`(무엇을 만드는가)와 `docs/sample_image/`(어떻게 보이는가)를 **어떻게 만드는가**로 옮긴 문서 묶음.

이 기획안은 스펙을 하나도 바꾸지 않는다. 스펙 §0.2가 의도적으로 비워 둔 영역 — 기술 스택, 파일 구조, 시스템 경계, 연출 수치, 사운드 합성, 검증 방법 — 만 채운다.

## 두 계약, 그리고 충돌 시 규칙

이 프로젝트에는 원본 계약이 둘 있다.

| 계약 | 위치 | 담당 |
|---|---|---|
| **기능 계약** | `docs/spec/기능_명세서.md` (1,566줄) | 규칙과 수치. 무엇이 참인가 |
| **비주얼 계약** | `docs/sample_image/` (15화면 + `engine.js` 2,047줄) | 그림. 무엇처럼 보이는가 |

비주얼 계약은 캡처 이미지가 아니라 **스펙을 실행해서 그린 그림**이다. `engine.js`가 §5의 패리 판정과 반사 공식을 실제로 돌리고, 각 화면은 적 배치와 발사 스케줄만 적는다. 화면에 보이는 GREAT는 실제로 거리 28u 안에서 성립한 GREAT다.

그런데 목업의 시뮬레이터는 절반만 구현돼 있어서 두 계약이 25곳에서 어긋난다.

> **충돌 시 규칙: 스펙이 규칙과 수치를 이기고, 목업이 외형을 이긴다.**

각 사례의 판정은 [10_스펙_목업_불일치.md](10_스펙_목업_불일치.md)에 있다. 그리고 목업이 **한 번도 그리지 않은** 스펙 요구가 11종 있는데, 이건 고칠 것이 아니라 새로 설계할 것이므로 [06_렌더링과_게임필.md](06_렌더링과_게임필.md) §5가 담당한다.

## 목업 코드를 어떻게 쓰는가

`docs/sample_image/_shared/engine.js`는 **완성된 렌더러 + 정확한 패리 수학 + 절반짜리 시뮬레이터**다.

| 부분 | 처리 |
|---|---|
| `draw*` 함수군 약 1,500줄 | **그대로 이식한다.** 승인된 아트 디렉션 그 자체다 |
| 상수 블록 (`PF`·`PARRY`·`BULLETS`·`ENEMIES`) | `config/`로 옮긴다. 값은 스펙과 1:1로 맞다 |
| `parry()`의 판정부 | 계산은 맞다. 다만 **입력 순간 1회**가 아니라 **활성 구간 매 스텝**으로 고친다 |
| `render()`의 레이어 순서 | 가독성 계약이므로 순서를 지킨다 |
| `still()` · `?at=` | **버린다.** 스틸 프레임 도구이지 게임이 아니다 |
| `autoParry()` | **버린다.** 대신 타이틀 어트랙트는 **기록된 입력을 고정 시드로 재생**한다 — 규칙 밖 경로를 코드에 남기지 않으면서 진짜 플레이를 보여 준다([12](12_통합_계약.md) §1 C-03) |
| 플레이어 피격, 상한, 점수, 카드, 게임 상태 | **존재하지 않는다.** 새로 만든다 |

## 스펙 자체의 모순 12건

기획안을 쓰다 발견한 것으로, 스펙이 자기 자신과 다른 값을 말하는 자리다. 구현이 어느 쪽을 따르는지는 [01_설계_결정.md](01_설계_결정.md) §4-B에 표로 있다.

| # | 항목 | 채택 |
|---|---|---|
| S-01 | E07 반사탄 데미지 (−25% vs −20%) | **−25%** |
| S-02 | R10 최소 간격 (0.12초 vs 0.06초) | **0.12초** |
| S-03 | §11.6 보정 순서 단계 수 (8 vs 9) | **8단계 + 스냅샷 확정** |
| S-05 | S3 근접·돌격 비율 25% vs 편성에 근접적 0기 | **편성이 이긴다 (0%)** |
| S-06 | HR-03 "완화 불가" vs §9.1의 소강 3초 예외 | **§9.1 (예외는 실재한다)** |
| S-07 | 잔존 적 4초 유예 vs 소강 3초 | **소강 3초** |
| S-08 | 히트스톱 예산 0.30 vs 0.32 | **0.32초** |
| S-09 | 보스 HP "100 단위 반올림" vs 1450·2250·3850 | **표의 값 (실제는 50 단위)** |
| S-10 | 20기에 닿는 스테이지 S4·S5 vs S5만 | **S5 W5만** |
| S-11 | 반사 속도 468~878 vs 공식상 468~780 | **468~780 u/s** |
| S-12 | §7.1 추격표에 P11 누락 + 반사 후 유도 미정의 | **반사되면 유도 즉시 소멸** (2026-08-08 판정) |
| S-13 | S5 보스 도달 "약 6분" vs 6분 53초 | **6분 53초** |
| S-14 | 검산 2 머리말이 N04·R10을 적고 안 씀 | **계산이 맞다** |

**셋이 아니라 열둘이다.** 원래 셋(S-01~S-03)은 §11.6 검산 블록이 개정 전 값을 든 경우였고, 나머지 아홉은 전수 대조에서 새로 나왔다. **열둘 다 채택값이 정해져 있어 구현을 막지 않는다.** 마지막까지 열려 있던 S-12(반사된 P11의 유도)는 2026-08-08에 닫혔다 — **반사되면 유도를 즉시 잃고 직진한다.** 남겨 두면 플레이어가 쳐낸 탄이 플레이어를 다시 쫓아오고, 그건 §7.1이 반사탄을 위험하게 만든 방식("따라가면 맞는다")이 아니다.

S-01·S-02는 밸런스에 직접 영향이 있다. R10을 0.06초로 구현하면 유효 패리 빈도가 기준 대비 +60%가 되어 §14.4의 보스 HP 산출 전제를 벗어난다.

## 규칙끼리 부딪히는 자리 1건

위 열둘과 종류가 다른 것이 하나 더 있다. 값은 전부 맞는데 **두 규칙이 동시에 성립할 수 없는 좌표가 실재한다.** 상세와 구현 임시 규칙은 [01_설계_결정.md](01_설계_결정.md) §4-C에 있다.

| # | 항목 | 상태 |
|---|---|---|
| S-04 | HR-09 억제 거리(최대 458u)가 §3.1의 플레이어·보스 영역 간 최소 거리 100u보다 커서, 보스 바로 아래 358u 띠에서 보스가 아무것도 못 쏜다. 탄이 없으면 반사탄도 없으므로(HR-01) 교착이 되고, HR-03 가드가 정상 플레이 중에 던진다 | **소유자 판단 대기.** 진짜 고침은 §3.1 또는 §10의 개정이라 기획안이 못 한다 |
