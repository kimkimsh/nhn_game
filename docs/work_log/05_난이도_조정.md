# 난이도 조정 — 스펙 §14.1 위에 얹은 배율

소유자가 체감 난이도가 너무 높다고 판단해 스펙 §14.1의 값 위에 일괄 배율을 얹었다.
**지금 게임이 쓰는 값은 `src/config/`이고 스펙 §14는 그 유래다.** 이 문서가 둘 사이의 차이표다.

## 배율

| 축 | 배율 | 사는 곳 |
|---|---|---|
| 탄속 | × 0.50 | `config/difficulty.ts`의 `bulletSpeedMul` |
| 잡몹 HP | × 2/3 | `config/difficulty.ts`의 `enemyHpMul` |
| 보스 HP | × 2/3 | `config/bosses/boss-N-*.ts`의 `hp` (B3는 `parts[].hp`도) |
| 발수 | × 0.7 (반올림, 최소 1) | `config/enemies.ts`의 `shotsPerCycle`, `config/bosses/*`의 발수 열 |
| 발사 간격 | × 1.4 | `config/enemies.ts`의 `fireCycleSec`, `config/bosses/*`의 간격 열 |

발수 × 0.7과 간격 × 1.4를 곱하면 초당 탄 수가 약 절반이 된다. 두 축으로 나눈 이유는 한쪽만
쓰면 형태가 무너지기 때문이다 — 발수만 반으로 줄이면 2발 부채꼴이 단발이 되어 사라지고,
간격만 두 배로 하면 함포문이 8초에 한 번 쏘는 정지 화면이 된다.

**반올림 때문에 실제 감소폭은 축마다 45~55% 사이에서 흔들린다.** 정확히 절반이 아니다.

## 배율을 안 먹인 것

| 대상 | 이유 |
|---|---|
| `tellSec` (발사 예비동작) | §14.2 난이도 축 2다. 요청은 축 1(탄속)과 축 3(밀도)에 대한 것이었다 |
| `maxEnemyBullets` | 성능 방어선이고 실측 도달치가 상한의 절반 이하다 — 내려도 체감이 안 바뀐다 |
| `waveCount` · `targetLengthSec` · `unparryable` | 편성과 구조이지 난이도 배율이 아니다 |
| `moveSpeedUPerSec` (잡몹 이동) | §14.1의 배율은 탄속에만 걸린다(10_스펙_목업_불일치.md A16) |
| B5 페이즈 4의 `lance.intervalSec` | P12는 패리 불가라 「탄약」이 아니고, 그 간격은 §10.6 3패턴 순환의 1/3 빈도에서 유도한 값이라 발사 주기와 다른 근거 위에 있다 |
| `summon`의 `count` (B1 E-D 4기, B3 소형선은 volley라 별개) | 적 수이지 탄 수가 아니다 |
| B3 좌현 일제포격의 `count: 1` | 발사원이 `parts`라 발수를 살아남은 포문 수가 정한다. 여기를 줄이면 부위 파괴의 보상이 사라진다 |

## 「발수」가 어느 열에 사는가

패턴마다 다르다. **`count`와 `repeat` 중 1보다 큰 쪽 하나만 줄였다** — 둘 다 줄이면 이중 감산이다.

| 패턴 | 발수를 담은 열 |
|---|---|
| B1 일제사격 · 강화, B5 총력 일제사격 · 전현 포격 · 조총/함포 일제 | `count` |
| B1 엄폐 전진, B3 갑판 조총 사격 · 교차 포격, B4 대통 직사 | `repeat` (`count`는 1이다) |
| 링 · 확산 · 참격파 연발 · 난사 · 곡사 예고 원 | `count` |

## 스펙과 어긋난 자리

**§14.4 검산표는 이 배율을 반영하지 않았다.** 그 표의 보스 격파 시간(24/27/29/32/37초),
T-03의 「NOT BAD 3발 이내」, T-01·T-02의 추정 DPS는 전부 원값 위에서 나온 숫자다.
`config/`를 다시 만질 때 그 표를 근거로 쓰면 안 된다.

같은 이유로 §6.2의 억제 거리 검산 458u도 지금은 229u다.

스펙 본문은 고치지 않았다. 고치려면 §14.1 표 · §14.4 검산표 · §6.2 검산 · §8.1 아키타입 표 ·
§10.2~§10.7 보스 패턴 전부를 함께 다시 세워야 하고, 그것은 밸런스 재설계이지 튜닝이 아니다.

## 실측 — `npm run balance` 전후

봇의 유효 패리/초가 0.550으로 §14.4 전제 2.08의 26%다. **아래 숫자는 봇의 것이고 사람의 것이
아니다.** 봇은 x축으로만 정렬하고 반사탄을 쫓지 않는다.

| 항목 | 전 | 후 |
|---|---|---|
| 판정 실패 | 24건 | 17건 |
| 가드 위반 | HR-03 160건 | **0건** |
| 보스 격파 (45런 합계) | 0회 | B1 2회 |
| 스테이지 클리어 | 0회 | S1 2회 |
| T-06 자해 비율 | 0.0% | 3.0% (합격선 15% 아래, 개별 런 3건은 초과) |
| 동시 적탄 최고 (S1 / S5) | 40 / 42 | 36 / 36 |
| 패리 시도 | 1,882회 | 2,832회 |
| 평균 등급 배수 | 1.821 | 1.743 |

**HR-03 위반 160건이 0건이 된 것은 부수 효과다.** 탄이 절반 속도로 날면 화면에 머무는 시간이
두 배가 되고, 「적 탄환이 하나도 없는 2.0초」가 성립하지 않는다. 00_진행_상황.md의 위험 R2가
이 조정으로 관측에서 사라졌다 — 조문이 고쳐진 것은 아니므로 스펙 개정 대기는 그대로다.

**새로 드러난 것 둘.**

- **T-04 스테이지 클리어 시간이 처음으로 판정 가능해졌고, 그리고 실패했다.** S1 실측 279초,
  목표 70초에서 +299%다. 전에는 클리어가 0건이라 「미측정」이었으므로 이것은 새 결함이 아니라
  새로 보이게 된 결함이다. 봇 DPS가 전제의 26%라는 사실이 이 숫자의 대부분을 설명한다.
- **T-06 반사탄 자해가 0%에서 3.0%로 올라왔다.** 반사탄 속도는 원래 탄속에서 유도되므로
  (`sim/reflect.ts`) 탄속 × 0.5가 반사탄 속도도 절반으로 만들었고, 이동 속도 520u/s인
  플레이어가 자기 반사탄을 따라잡기 쉬워졌다. §14.3 T-06이 이 경우의 조치를 못 박아 두었다 —
  **자해 유예(`config/reflect.ts`의 `graceSec`, 현재 0.15초)를 먼저 늘리고 반사탄 속도나
  이동 속도는 건드리지 않는다.** 아직 적용하지 않았다.

## 테스트가 따라 움직인 자리

값이 바뀌어 기대값을 다시 세운 곳이다. 단언을 약하게 만든 곳은 없다.

| 파일 | 무엇 |
|---|---|
| `tests/guards.test.ts` | HR-09 억제 거리 458 → 229, B1 HP 1450 → 967 |
| `tests/progress.test.ts` | B3 본체 2000 → 1333, 포문 300 → 200, 두 임계값을 한 번에 지나는 데미지 1600 → 1066 |
| `tests/reflect.test.ts` | 반사탄 속도 상한 2400 검사에 N06 3중첩을 더했다. 탄속이 절반이 된 뒤로는 카드 없는 최고속 조합이 1533u/s라 상한에 닿지 않아, 그대로 두면 상한을 검사하지 않는 테스트가 된다 |
| `tests/determinism.test.ts` | 런 길이 4004ms → 8008ms. 탄 비행 시간이 두 배가 되어 4초 창에서는 한 발도 도착하지 않았고, 「빈 세계가 아니다」 단언이 무너졌다 |
