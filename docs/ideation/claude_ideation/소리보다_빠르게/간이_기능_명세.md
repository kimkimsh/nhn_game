# 소리보다 빠르게 — 간이 기능 명세

스택: TypeScript(strict) + HTML5 Canvas 2D + Web Audio API. 프레임워크·물리엔진 없음.

---

## 1. 데이터 모델

```ts
interface Ring {
  cx: number; cy: number;   // 진원지 (고정)
  radius: number;           // 매 프레임 speed * dt 만큼 증가
  speed: number;            // 물건 종류에서 결정
  thickness: number;        // 판정 두께
  age: number;              // 렌더 알파 계산용
}

interface Breakable {
  x: number; y: number;
  kind: 'glass' | 'wood' | 'metal';
  broken: boolean;
}

interface Stage {
  objects: Breakable[];     // 손으로 배치
  targetScore: number;      // 승리 조건
  bounds: { w: number; h: number };
}
```

**링은 원 하나다.** 파동 시뮬레이션이 아니라 반지름 스칼라 하나가 증가하는 것뿐이다.

## 2. 핵심 알고리즘

### 2-1. 링 확장과 판정

```
매 프레임:
  각 ring:
    ring.radius += ring.speed * dt
    ring.age    += dt
    if ring.radius > MAX_RADIUS: 제거

  플레이어 사망 판정:
    d = distance(player, ring.center)
    if abs(d - ring.radius) < ring.thickness / 2 + PLAYER_R  → 사망
```

**절대값 밴드 판정**이다. 링 안쪽은 안전하고 링 자체만 위험하다. 이것이 "이미 지나간 소리는 나를 못 잡는다"를 만든다.

### 2-2. 물건 종류별 상수

```ts
const KIND = {
  glass: { speed: 260, thickness: 4,  score: 10 },
  wood:  { speed: 150, thickness: 12, score: 25 },
  metal: { speed: 130, thickness: 16, score: 50 },
} as const;
```

**튜닝 파라미터는 이 표 + `RING_LIFETIME` 하나뿐이다.** 이 이상 늘리면 7일 안에 수렴하지 않는다.

### 2-3. 부수기

```
플레이어가 Breakable 반경 안에 들어가면 자동으로 부순다 (버튼 없음)
  → broken = true, 점수 += KIND[kind].score
  → 그 좌표에 Ring 생성
```

입력을 이동 하나로 유지한다. 부수기 버튼을 따로 두면 "왜 안 부숴지지"가 생긴다.

## 3. 입력

| 입력 | 동작 |
|---|---|
| WASD / 방향키 | 8방향 이동 (등속, 관성 없음) |
| R | 재시작 |
| Esc | 스테이지 선택 |

**관성·가속도 없음.** 결정론적 이동이라 헤드리스 검증이 성립한다.

## 4. 렌더링 규칙 (중요)

```
링:  stroke만. fill 금지.
     lineWidth = thickness
     globalAlpha = 1 - (age / RING_LIFETIME)   // 나이에 비례해 흐려짐
     색: 원색 (예: #FF3B30, #FF9500, #007AFF) — 종류별로 다름
배경: 밝은 단색 (#F5F5F0 급)
```

fill을 쓰면 링 5개가 겹칠 때 화면이 뭉개진다. 밝은 배경 + 원색 링은 `Dark Echo`(어두운 배경 + 흰 파면)와 첫인상을 벌리기 위한 필수 조건이다.

## 5. 화면 구성

한 화면. 카메라 이동 없음. 스테이지 전체가 한 프레임에 들어간다.

```
┌────────────────────────────────┐
│ 스테이지 4/8   점수 180/250     │
│    ╭──────────╮                │
│   ╭┴──╮    ▣  │  ▣ = 안 부순 물건│
│   │ ╭─┴╮     ╰────╮            │
│   │ │ ●│  ← 플레이어             │
│   │ ╰──╯  ▣      │             │
│   ╰────╮        ╱              │
│  ▣      ╰──────╯     ▣         │
│                                │
│  (겹친 링들의 틈이 안전 통로)      │
└────────────────────────────────┘
```

## 6. 게임 상태 머신

```
타이틀 → 스테이지 선택 → 플레이
   → (목표 점수 도달) → 클리어 → 다음 스테이지
   → (링 접촉) → 패배 → 즉시 재시작
   스테이지 8 클리어 → 최종 화면
```

스테이지 선택을 두어 심사자가 5분 안에 최종 화면까지 갈 수 있게 한다.

## 7. 오디오 (Web Audio 절차 생성)

| 사건 | 합성 |
|---|---|
| 유리 | 고역 노이즈 버스트 + 짧은 감쇠 |
| 나무 | 중역 임펄스 + 밴드패스 |
| 금속 | 저역 + 긴 링잉(감쇠 사인) |
| 사망 | 저역 스윕 다운 |
| 클리어 | 상승 3음 |

**무음 필수 조건**: 링이 시각적으로 완전히 보이므로 소리를 꺼도 게임이 성립한다. 소리는 종류 구분의 **중복 전달**일 뿐 정보를 독점하지 않는다.

## 8. 검증 하네스 (이 안의 핵심 자산)

```
scripts/sweep-lifetime.ts
  RING_LIFETIME 값 20개 (0.5초 간격) × 각 100판
  자동 정책: 가장 가까운 미파괴 물건으로 이동, 링 밀도가 가장 낮은 방향으로 회피
  출력 JSON:
    - 평균 생존 시간
    - 목표 점수 달성률
    - "이동 가능 면적이 0이 되는 시점" 분포
  곡선을 그려 후보 3개를 뽑고, 사람은 그 3개만 손으로 플레이한다
```

이틀짜리 감각 튜닝을 반나절로 줄이는 장치이자, **AI 활용 기술 문서에서 "밸런스를 감이 아니라 수치로 판정했다"의 증거물**이다.
