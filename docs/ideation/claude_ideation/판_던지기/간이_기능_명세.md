# 판 던지기 — 간이 기능 명세

스택: TypeScript(strict) + HTML5 Canvas 2D + Web Audio API. **물리 엔진 없음** — 포물선 + 회전은 닫힌 식으로 직접 적분한다.

---

## 1. 데이터 모델

```ts
interface Board {              // 던지는 과녁
  x: number; y: number;
  vx: number; vy: number;
  angle: number;               // 현재 회전 위상 (rad)
  angularVel: number;          // 라운드별 고정 상수 ← 입력 아님
  radius: number;
  stuck: StuckDart[];          // 꽂힌 다트 (로컬 좌표로 보관)
}

interface StuckDart {
  localAngle: number;          // 원판 로컬 좌표계 기준 각도
  localR: number;              // 중심으로부터 거리
  score: number;
}

interface FloatingDart {
  x: number; y: number;
  tipDir: number;              // 촉이 향한 방향 (rad)
  spin: number;                // 제자리 회전 (후반 라운드)
  bobPhase: number;            // 상하 흔들림
  kind: 'normal' | 'bomb';
  consumed: boolean;
}
```

## 2. 핵심 알고리즘

### 2-1. 앞면/뒷면 판정 — **1일차에 단위 테스트로 먼저 고정**

```
충돌 순간:
  원판 법선 n = (cos(board.angle), sin(board.angle))
  다트 촉 진행 방향 d = (cos(dart.tipDir), sin(dart.tipDir))

  dot = n.x * d.x + n.y * d.y

  dot < 0  → 촉이 앞면을 향해 들어옴 → 꽂힌다
  dot >= 0 → 뒷면 → 튕긴다
```

**부호를 반대로 잡으면 모든 던지기가 튕겨 게임이 성립하지 않는다.** 그래서 게임 루프보다 먼저 짠다.

```
test/normal-sign.test.ts
  법선 8방향 × 촉 8방향 = 64가지 조합을 손으로 계산한 기대값과 대조
```

### 2-2. 꽂힌 다트의 로컬 좌표 변환 — **2일차까지 필수**

```
꽂히는 순간:
  worldAngle = atan2(dart.y - board.y, dart.x - board.x)
  localAngle = worldAngle - board.angle      // 원판 기준으로 고정
  localR     = distance(dart, board.center)

렌더링 시:
  drawAngle = board.angle + localAngle       // 원판과 함께 회전
  drawX = board.x + cos(drawAngle) * localR
  drawY = board.y + sin(drawAngle) * localR
```

이 변환이 없으면 꽂힌 다트가 원판과 함께 돌지 않아 화면이 즉시 이상해진다.

### 2-3. 비행 (물리 엔진 불필요)

```
매 프레임 (고정 dt):
  board.vy    += GRAVITY * dt
  board.x     += board.vx * dt
  board.y     += board.vy * dt
  board.angle += board.angularVel * dt        // 고정 상수, 감속 없음
```

3줄이다. 강체 솔버도 접촉 해소도 없다.

### 2-4. 충돌 검사

```
각 미소비 FloatingDart에 대해:
  d = distance(dart, board.center)
  if d < board.radius:
      앞면/뒷면 판정 → 꽂힘 또는 튕김
      dart.consumed = true
```

원-점 거리 하나. 프레임당 다트 수가 10 미만이라 공간 분할도 불필요.

## 3. 입력

| 입력 | 동작 |
|---|---|
| 드래그 (당겼다 놓기) | 방향 + 세기. **스핀은 입력에 없다** |
| R | 라운드 재시작 |
| Esc | 라운드 선택 |

```
발사:
  drag = dragStart - dragEnd
  board.vx = drag.x * SPEED_SCALE
  board.vy = drag.y * SPEED_SCALE
  board.angularVel = STAGE_SPIN[currentRound]   // 고정 상수
```

플레이어가 실제로 조절하는 것은 **"언제 놓는가"**다. 다트가 흔들리고 회전하므로 같은 드래그도 놓는 시점에 따라 결과가 다르다.

## 4. 튜닝 파라미터 — 정확히 3개

```ts
const GRAVITY     = 900;   // px/s²
const SPEED_SCALE = 3.2;   // 드래그 픽셀 → 초기 속도
const STAGE_SPIN  = [4.0, 5.5, 7.0, 8.5, 10.0, 12.0, 14.0, 16.0]; // rad/s
```

**이 이상 늘리지 않는다.** 늘리는 순간 7일 안에 수렴하지 않는다.

## 5. 화면 구성

한 화면. 카메라 이동 없음.

```
┌─────────────────────────────────┐
│ 라운드 3/8      점수 240         │
│                                 │
│                  ↑ ↗            │  ← 떠 있는 다트 (촉 방향 표시)
│         ╭───╮      ↗            │
│        ╱  ✕  ╲    ←             │  ← 날아가는 과녁 (회전)
│        ╲     ╱  ↑               │
│         ╰───╯                   │
│                     ↘           │
│   ◜◝                            │
│  (당김 궤적 프리뷰)               │
│ ═══════════════════════════════ │  ← 바닥
└─────────────────────────────────┘
```

다트의 촉 방향이 **화살표 모양 자체로** 보여야 한다. 왜 튕겼는지가 눈으로 읽히는 것이 이 게임 영상의 전부다.

## 6. 게임 상태 머신

```
타이틀 → 라운드 선택 → 조준 → 비행 → 착지/파괴 → 결과
   → (목표 점수 도달) → 다음 라운드
   → (과녁 소진) → 패배 → 재시작
   라운드 8 클리어 → 최종 화면
```

## 7. 오디오 (Web Audio 절차 생성)

| 사건 | 합성 |
|---|---|
| 꽂힘 | 짧은 임펄스 + 나무 울림 (**연속 꽂힘 시 음정 상승** — 콤보 감각) |
| 튕김 | 금속 클링크, 고역 |
| 착지 | 저역 둔탁음 |
| 폭탄 | 노이즈 버스트 |

"툭, 툭, 툭" 연속음이 이 게임 영상의 청각 훅이지만, **무음으로도 다트가 박히는 그림이 전부 보여야 한다.**

## 8. 검증 — 이 안의 약점

헤드리스 시뮬로 검증 가능한 것: 라운드별 목표 점수가 **이론적으로 달성 가능한지**(최적 발사각 탐색).

검증 **불가능**한 것: 던지는 감각이 재밌는지. 이 게임의 재미는 손맛에 있고, 손맛은 자동 플레이가 알려주지 않는다.

**그래서 3일차 종료에 사람이 판정하고, 아니면 그날 밤 포기한다.** 이 한계를 AI 활용 기술 문서에 숨기지 않고 적는다 — "무엇을 자동화할 수 없었는가"도 방법론의 일부다.
