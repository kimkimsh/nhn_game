# 새치기 — 간이 기능 명세

스택: TypeScript(strict) + HTML5 Canvas 2D + Web Audio API. 프레임워크·물리엔진 없음.

---

## 1. 데이터 모델

```ts
interface Person {
  id: number;
  anger: number;          // 0.0 ~ 1.0
  cutCount: number;       // 나에게 제쳐진 횟수 (2회부터 분노 2배 가속)
  slotY: number;          // 렌더용 보간 위치
}

interface Queue {
  people: Person[];       // 인덱스 0 = 맨 앞 (창구에 가장 가까움)
  counterTimer: number;   // 고정 주기. 무작위 정지 없음
}

interface GameState {
  queues: Queue[];        // 6개
  playerQueue: number;    // 현재 내가 선 줄
  playerIndex: number;    // 그 줄에서의 위치
  score: number;          // 제친 누적 인원
  throwCount: number;     // 투척당한 횟수 (3회 = 패배)
  timeLeft: number;       // 60초
}
```

**모든 위치가 배열 인덱스다.** 화면 좌표는 인덱스에서 계산되고, 움직임은 슬롯 간 시간 보간일 뿐이다. 충돌 판정·중력·관성이 존재하지 않는다.

## 2. 핵심 알고리즘

### 2-1. 끼어들기 (`splice` 한 줄)

```
cutIn(targetQueue, targetIndex):
  제친 인원 = 대상 줄에서 targetIndex 뒤에 서 있던 사람 수

  1. 현재 줄에서 나를 제거
  2. queues[targetQueue].people.splice(targetIndex, 0, player)
  3. 밀려난 인원 = people.slice(targetIndex + 1)
  4. score += 밀려난 인원 수
  5. 밀려난 각 사람:
       anger += ANGER_PER_CUT * (cutCount >= 1 ? 2 : 1)
       cutCount += 1
       분노 아이콘 점등을 인덱스 순서대로 지연 트리거 (연출)
```

### 2-2. 분노와 투척

```
매 프레임, 내가 선 줄의 내 뒤 사람들만:
  anger -= COOL_RATE * dt        // 냉각. 후반 스테이지일수록 느려짐
  anger = clamp(anger, 0, 1)

  줄의 평균 anger >= THROW_THRESHOLD 이면:
    → 붙잡혀 그 줄 맨 뒤로 투척
    → throwCount += 1, 카메라 흔들림
    → 그 줄 전원 anger 리셋
```

### 2-3. 창구 처리 — **고정 주기**

```
매 프레임 각 줄:
  counterTimer -= dt
  if counterTimer <= 0:
    people.shift()               // 맨 앞 사람 퇴장
    counterTimer = COUNTER_PERIOD  // 무작위 정지·재개 없음
    뒤에서 새 사람 1명 유입
```

**무작위 정지를 넣지 않는다.** 이것이 `Queue Up!`과 갈라서는 유일한 지점이자, 난이도 축을 "어느 줄이 빠른가"에서 "얼마나 깊이 꽂을 것인가"로 옮기는 장치다.

## 3. 입력

| 입력 | 동작 |
|---|---|
| 마우스 이동 / 터치 드래그 | 삽입 지점 프리뷰 (어느 줄, 어느 깊이) |
| 클릭 / 탭 | 그 지점으로 끼어들기 |
| R | 재시작 |

**삽입 지점 프리뷰가 필수다.** 클릭 전에 "몇 명을 제치게 되는지"와 "그들의 현재 분노"가 미리 보여야 판단이 성립한다.

## 4. 화면 구성 (첫 프레임 구도 주의)

`Queue Up!`과 실루엣을 벌리기 위해 **줄을 가로로 눕히고 창구를 오른쪽 세로 배치**한다.

```
┌──────────────────────────────────────┐
│ 점수 47/100    ⏱ 38초   투척 1/3     │
│                                      │
│ ●●●○●●●●●●●●●●●              ▐ 창구  │
│ ●●●●●●●●●●●                  ▐ 창구  │
│ ●●●▲●●●●●●●●●●●●●            ▐ 창구  │  ▲ = 나
│ ●●●●●●●●●●●●●●●●●●           ▐ 창구  │
│ ●●●●●●●●                     ▐ 창구  │
│ ●●●●●●●●●●●●                 ▐ 창구  │
│      ╰─ 분노 점등이 여기서 왼쪽으로 번짐 │
│                                      │
│  [프리뷰]  여기 끼어들면 +9  (분노 중간) │
└──────────────────────────────────────┘
```

- 분노 단계는 색으로: 흰 → 노랑 → 주황 → 빨강
- 밀려난 사람들은 **실제로 한 칸씩 이동**하고 줄이 눈에 보이게 길어진다

## 5. 게임 상태 머신

```
타이틀 → 플레이
   → (점수 100 도달) → 승리 연출 → 최종 화면
   → (투척 3회) → 패배
   → (60초 종료) → 점수 결과
   재시작 / 종료
```

## 6. 오디오 (Web Audio 절차 생성)

| 사건 | 합성 |
|---|---|
| 끼어들기 성공 | 짧은 상승음, **제친 인원수에 비례해 음정 상승** |
| 분노 점등 | 짧은 틱, 순차 재생(연쇄 감각) |
| 투척 | 저역 임팩트 + 노이즈 |
| 창구 통과 | 부드러운 2음 |
| 승리 | 상승 아르페지오 |

무음으로도 성립 — 제친 인원수·분노 색·줄 길이가 전부 시각 정보다.

## 7. 검증 하네스

```
scripts/balance-sim.ts
  정책 3종으로 각 1000판 자동 플레이
    A: 항상 얕게(3명 이내)   B: 항상 깊게(10명 이상)   C: 분노 최저 줄 우선
  출력: 정책별 평균 점수, 투척 횟수, 60초 내 목표 달성률
  판정: 세 정책의 점수 차가 20% 이내면 "선택이 무의미"하므로 실패
```

**이 검증이 이 게임의 핵심 질문에 답한다** — 삽입 깊이 선택이 실제로 의미 있는 트레이드오프인가, 아니면 한 가지 전략이 항상 우월한가. 후자면 게임이 없는 것이다.

## 8. 7일 일정

| 일차 | 작업 |
|---|---|
| D1 | 배포 파이프라인, 고정 타임스텝 루프, 대기열 자료구조 + 창구 처리 |
| D2 | 끼어들기·분노·냉각·투척 — 코어 완성. `balance-sim.ts` 로 정책 차이 검증 |
| D3~D4 | **연출 집중** — 밀려남 애니메이션, 분노 순차 점등, 프리뷰 UI, 투척 카메라. 콘텐츠 동결 |
| D5~D6 | 폴리시 — 이징, 히트스톱, 스크린셰이크, 오디오, 승리·패배 화면 |
| D7 | 영상, PDF 3종, 링크 검증 |

**일정의 특징**: 구현이 이틀에 끝나고 연출에 이틀을 쓴다. 이 게임은 로직이 아니라 연출이 재미의 실체다.
