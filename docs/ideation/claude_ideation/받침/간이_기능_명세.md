# 받침 — 간이 기능 명세

스택: TypeScript(strict) + HTML5 Canvas 2D + Web Audio API. 프레임워크·물리엔진 없음.

---

## 1. 데이터 모델

```ts
// 한 칸에 놓인 글자
interface Cell {
  char: string;        // 완성형 음절 1자
  jongseong: 0 | 1 | 2; // 받침 없음 / 홑받침 / 겹받침 = 지지력
  frozen: boolean;      // 세로 단어 성립으로 굳었는가 (지지력 무한)
}

interface Board {
  cols: number;              // 고정 (권장 7)
  grid: (Cell | null)[][];   // [row][col], row 0 = 바닥
  load: number[][];          // 각 칸의 누적 하중 (정수)
}

interface Stage {
  targetHeight: number;   // 승리 조건
  sequence: string[];     // 손으로 짠 고정 낙하 순서
}
```

**모든 상태가 정수·불리언이다.** 실수 좌표는 렌더링에만 존재한다.

## 2. 핵심 알고리즘

### 2-1. 음절 분해 (받침 추출)

```
코드포인트 = char - 0xAC00
종성인덱스 = 코드포인트 % 28
종성인덱스 == 0        → jongseong = 0
겹받침 테이블에 포함    → jongseong = 2   (ㄳㄵㄶㄺㄻㄼㄽㄾㄿㅀㅄ)
그 외                  → jongseong = 1
```

### 2-2. 하중 전파 (물리 엔진 대체)

착지 이벤트 1회당 아래 방향으로 1회 순회한다. 매 프레임 전체 재계산 금지.

```
착지 칸에서 시작
  아래로 내려가며 load[row][col] += 1
  각 칸에서 load > jongseong 이고 frozen == false 이면
    → 그 칸을 붕괴 시작점으로 표시하고 순회 종료
붕괴 시작점이 있으면 그 위쪽 전체를 낙하 트윈으로 흩뿌리고 제거
```

계산량은 탑 높이에 비례하고 상태는 정수뿐이다. 결정론이 보장되므로 헤드리스 검증이 성립한다.

### 2-3. 세로 단어 판정

착지 직후, 착지 칸과 바로 아래 칸의 2글자를 사전에 조회한다.
- 사전은 정적 `Set<string>`, 300~500개
- **양방향 인정** (위→아래, 아래→위 둘 다 조회)
- 성립하면 두 칸 모두 `frozen = true`, 색 변경 + 효과음

## 3. 입력

| 입력 | 동작 |
|---|---|
| ← → | 낙하 글자 좌우 1칸 이동 |
| ↓ | 즉시 낙하 |
| R | 재시작 |
| Esc | 타이틀 |

터치: 화면 좌/우 절반 탭 = 좌우 이동, 아래 스와이프 = 즉시 낙하.

## 4. 화면 구성

한 화면에 전부 들어간다. 카메라 이동·씬 전환 없음.

```
┌─────────────────────────┐
│ 스테이지 3/8   목표 12칸 │  ← HUD
│                         │
│        [낙하 글자]       │
│                         │
│         ▓ 목표선 ▓       │  ← 점선
│        ┌─┐              │
│        │갈│ ← 굳은 칸(색 다름)
│        ├─┤              │
│        │산│              │
│        ├─┤              │
│  ┌─┐   │곰│   ┌─┐       │
│  │나│   ├─┤   │말│       │  ← 받침 없는 글자는 위가 막힘 표시
│  └─┘   │밥│   └─┘       │
│ ════════════════════════ │  ← 바닥
└─────────────────────────┘
```

- 겹받침 글자: 테두리 두 겹
- 받침 없는 글자: 윗면에 사선 해칭 (여기 못 올림)
- 굳은 칸: 채움색 반전

## 5. 게임 상태 머신

```
타이틀 → 플레이 → (목표 높이 도달) → 스테이지 클리어 → 다음 스테이지
                → (탑 붕괴로 높이 0) → 패배 → 재시작
        스테이지 8 클리어 → 최종 화면
```

**5개 상태 전부 구현 필수.** 심사자가 5분 안에 최종 화면에 도달할 수 있어야 하므로 스테이지 셀렉트를 둔다.

## 6. 오디오 (Web Audio 절차 생성, 외부 파일 0개)

| 사건 | 합성 |
|---|---|
| 착지 | 짧은 사각파 + 빠른 감쇠 |
| 굳음(단어 성립) | 3화음 아르페지오 상승 |
| 붕괴 | 노이즈 버스트 + 저역 통과 스윕 |
| 스테이지 클리어 | 5도 상승 2음 |

**무음으로도 전부 이해되어야 한다.** 오디오는 보강일 뿐 정보를 독점하지 않는다.

## 7. 검증 하네스 (AI 활용 기술 문서의 핵심 증거)

```
scripts/balance-sim.ts
  렌더 없이 로직만 실행
  스테이지별로 1만 판 자동 플레이 (탐욕 정책: 받침 있는 칸 우선)
  출력: 클리어율, 평균 착지 수, 붕괴 발생 위치 분포
  허용 범위(클리어율 25~45%) 위반 시 exit 1
```

하중이 정수 누적이라 상태공간이 작다. 스테이지 목표 높이가 실제로 도달 가능한지를 휴리스틱 근사가 아니라 **탐색으로 증명**할 수 있다. 4일차 밸런스 판단에서 "감으로는 될 것 같은데"와 "1만 판 돌렸고 클리어율 34%다"의 차이를 만든다.

`window.__game`에 스코어·높이·붕괴 카운트를 노출해 Playwright가 읽게 한다.
