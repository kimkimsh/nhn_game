# 식혀 꽂기 — 간이 기능 명세

> 고도화 전 단계의 골격만. 수치는 전부 튜닝 대상이다.

## 화면 구성

한 화면 고정. 카메라 이동 없음. 스크롤 없음.

```
┌──────────────────────────────────────────────────────────┐
│  격자판 (구멍 6~8개)                          ○ ← 손님    │
│   ┌─────────────────┐                         │  도형     │
│   │  ◌   ◌   ◌   ◌  │                        ═╪═ 실패작   │
│   │  ▮   ◌   ◌   ▮  │  ▮ = 박힌 막대           ╿  격자     │
│   └─────────────────┘  ◌ = 빈 구멍            ╿  (고드름)  │
│                                                          │
│         ╲                                                │
│          ╲ ← 팔: 선분 3마디 (Verlet)                      │
│           ╲                                              │
│            ▬▬▬ ← 쇠막대: 선분 4마디. 색 = 온도            │
│              ▲ 커서 (렌더 안 함)                          │
│                                                          │
│   ░░▒▒▓▓ ← 잔열 궤적. 지나간 자리가 붉게 남아 서서히 식음  │
└──────────────────────────────────────────────────────────┘
```

- **쇠막대**: 굵은 선분 4마디. HSL 색상만으로 온도를 표시한다. 파랑(0) → 주황 → 흰색(1). **게이지 바 없음 — 막대 자체가 게이지다**
- **팔**: 가는 선분 3마디 + 어깨 고정점 1개. 단색 회색
- **격자판**: 사각형 하나 + 원형 구멍. 박힌 막대는 짧은 선분, 실패한 막대는 아래로 흘러내려 굳은 물방울 모양
- **손님 도형**: 원 하나에 점 두 개. 표정 변화 없음. 실패 격자가 눈앞에 걸릴 때 한 번 기울어질 뿐
- **잔열**: 화면 격자 셀마다 붉은 알파. 게임플레이 오브젝트 뒤에 그린다
- HUD 없음. 숫자·타이머·점수 표시 없음

## 입력

| 입력 | 동작 |
|---|---|
| 마우스 이동 | 팔 끝 목표 위치. **이것이 전부다** |
| 아무 키 | 실패 후 즉시 재시작 |

버튼 없음. 클릭 없음. 냉각 버튼도 삽입 버튼도 없고, **손을 움직이는 속도 하나가 두 동작을 다 표현한다.**

## 핵심 시스템

물리 엔진 없이 네 계층. 전부 합쳐 백 줄 미만이다.

### 1) 입력 미화 — 2차 시스템 (t3ssel8r), 상수 3개 + 갱신 2줄

마우스 좌표를 물리에 직접 먹이지 않는다. 먼저 2차 시스템에 통과시켜 흔들린 입력을 곡선으로 만든다.

```
k1 = z / (PI * f)
k2 = 1 / ((2*PI*f) * (2*PI*f))
k3 = r * z / (2*PI*f)
y  += dt * yd
yd += dt * (x + k3*xd - y - k1*yd) / k2
```

`f`(응답 주파수) `z`(감쇠) `r`(선행 반응) 셋만 만진다. `r`을 양수로 두면 손이 꺾이기 전에 팔이 먼저 기울어 **손동작이 실제보다 유려해 보인다.** 구멍 반경 안에서는 `f`를 올려 스냅을 건다.

### 2) 팔과 막대 — Verlet + 거리제약, 6줄

팔 3마디 + 막대 4마디 = 점 8개짜리 체인 하나. 어깨는 고정, 손목은 위 2차 시스템의 출력 `y`로 매 프레임 강제한다.

```
// 적분
next = p + (p - pPrev) * DAMP + GRAVITY * dt * dt
pPrev = p; p = next
// 제약 (2~4회 반복)
d = b - a; len = length(d); diff = (len - rest) / len
a += d * 0.5 * diff
b -= d * 0.5 * diff
```

**엿가락 늘어짐은 새 코드가 아니다.** 막대 마디의 `rest` 길이를 온도의 함수로 늘리고 그 마디의 `GRAVITY`를 키우면, 같은 6줄이 축 처지는 그림을 낸다.

```
rest = rest0 * (1 + SAG_GAIN * max(0, heat - MELT_T))
```

**팔도 같은 체인이므로 막대가 늘어지면 팔이 자동으로 딸려 처진다.** 별도 연출 코드가 필요 없다.

### 3) 온도 — 지수감쇠 1줄

```
heat += (HEAT_BASE - coolRate) * dt        // 0..1로 clamp
coolRate = SPEED_GAIN * min(speed, SPEED_CAP) * (1 - residualAt(cursor))
```

`HEAT_BASE`는 상수다. **아무것도 안 하면 무조건 뜨거워진다.** 냉각은 커서 속도에 비례하고, 그 자리의 잔열만큼 깎인다.

### 4) 잔열 필드 — 셀 배열 + 지수감쇠 1줄

화면을 32×18 셀로 나눈다. 셀마다 `residual` 0~1.

```
셀 갱신:  residual *= exp(-RESIDUAL_DECAY * dt)
커서 통과: residual = max(residual, 1)   // 브러시 반경 BRUSH_R
```

**이 배열 하나가 이 게임의 깊이 전부다.** 같은 8자를 두 번 그리면 `residualAt`이 1에 가까워 `coolRate`가 0이 된다. 매번 새 궤적을 찾아야 하는 이유가 이 두 줄에서 나온다.

### 손맛 — 히트스톱 3단

정지 대상은 **충돌한 두 오브젝트만**. 팔·잔열·손님은 계속 움직인다.

| 사건 | 히트스톱(60fps 기준) |
|---|---|
| 막대 끝이 구멍 테두리를 때리고 튕김 | 약 3프레임 |
| 막대가 구멍에 완전히 박힘 | 중 6프레임 |
| 녹아내림이 시작되는 프레임 | 대 10프레임 → 이어서 0.8초 붕괴 재생 |

붕괴는 확률이 아니라 임계값이다. `heat > MELT_T`가 되는 순간 결정론적으로 같은 연출이 나온다. **30초 영상을 확률에 걸지 않는다.**

## 판정 규칙

| 조건 | 결과 |
|---|---|
| 막대 끝이 구멍 콜라이더 안 + 커서 속도 < `INSERT_SPEED_MAX` | 삽입 진행. `depth += dt / INSERT_SEC` |
| 커서 속도가 `INSERT_SPEED_MAX`를 넘음 | 삽입 중단, `depth` 유지된 채 막대가 빠져나옴 |
| `depth >= 1.0` | **성공.** 구멍이 채워지고 막대 교체 |
| 삽입 중 `heat > MELT_T` | **실패.** 0.8초 붕괴 — 늘어짐 → 흘러내림 → 굳음. 그 구멍은 영구히 막힌다 |
| 삽입 중이 아닐 때 `heat >= 1.0` | 막대가 손 안에서 늘어져 떨어진다. 구멍 손실 없이 막대만 교체(3초 페널티) |
| 막힌 구멍 수 > `FAIL_LIMIT` | **스테이지 패배** |
| 모든 구멍이 채워짐 | **스테이지 승리.** 손님이 격자를 받아 간다 |

실패한 구멍은 **복구되지 않는다.** 판이 끝나면 성공과 실패가 격자 한 장에 같이 남는다.

## 파라미터 (튜닝 대상)

| 이름 | 초기값 후보 | 무엇을 정하는가 |
|---|---|---|
| `HEAT_BASE` | 0.35 /초 | 정지 시 재가열 속도. 냉각창 길이의 하한 |
| `SPEED_GAIN` | — | 커서 속도 1당 냉각량 |
| `SPEED_CAP` | 화면폭 × 2.5 /초 | 무한 고속 휘두르기 상한 |
| `RESIDUAL_DECAY` | 0.25 /초 | 잔열이 식는 속도. **폐기 판정 대상 아님 — 봇 검증 대상** |
| `BRUSH_R` | 화면폭의 4% | 궤적 한 줄이 태우는 폭 |
| `MELT_T` | 0.85 | 녹아내림 임계 |
| `INSERT_SEC` | 0.9초 | 구멍 하나를 채우는 데 필요한 정지 시간 |
| `INSERT_SPEED_MAX` | 화면폭의 6% /초 | "거의 멈춤"의 정의 |
| `SAG_GAIN` | — | 엿가락 늘어짐 정도 |
| `FAIL_LIMIT` | 스테이지별 2~3 | 패배 문턱 |
| 냉각창 길이 | 약 1.0초 | `HEAT_BASE`와 `MELT_T`에서 유도되는 값. 직접 세팅하지 않는다 |

## 콘텐츠 분량

- 스테이지 **6개** + 명시적 최종 화면(완성된 격자 6장을 손님이 늘어놓는 화면)
- 1스테이지 **15~20초**, 구멍 3~8개
- 전체 완주 **2분 이내**
- 난이도 진행: 구멍 3개(넓음) → 구멍 5개 → 구멍이 화면 양끝으로 벌어짐 → `RESIDUAL_DECAY` 감소(잔열이 오래 남음) → 구멍 지름 축소 → 종합

레벨 셀렉트 필수. 심사자가 최종 화면에 도달하지 못하면 만든 것의 절반이 평가 대상에서 사라진다.

## 오디오 (Web Audio 절차 생성, 외부 파일 0개)

| 사건 | 소리 |
|---|---|
| 커서 고속 이동 | 화이트노이즈 밴드패스, 컷오프가 속도에 비례해 올라감 |
| 온도가 냉각창에 진입 | 사인파 2음 짧게 (창이 열림) |
| 막대가 구멍 테두리를 때림 | 짧은 클릭 노이즈 |
| 삽입 진행 중 | 저역 사인파, `depth`에 따라 반음씩 상승 |
| 삽입 성공 | 상승 마무리음 + 짧은 저역 임팩트 |
| 녹아내림 0.8초 | 톱니파 피치가 아래로 미끄러짐 |
| 손님이 격자를 받음 | 3음 아르페지오 |

**무음으로도 전부 이해된다.** 온도는 색, 창은 색 변화, 삽입은 막대가 들어가는 그림, 실패는 흘러내림. 소리는 전부 화면 정보의 중복이다.

## 승패와 흐름

```
타이틀 ──► 스테이지 선택 ──► 플레이 ──┬──► 승리 ──► 다음 스테이지
             ▲                        │
             │                        └──► 패배 ──► 재시작
             └────────────────────────── 최종 화면 ◄── 6스테이지 클리어

플레이 내부:
  가열 ⇄ 냉각 ──► 창 열림 ──► 삽입 ──┬──► 박힘
                                     └──► 붕괴(0.8초, 스킵 불가)
```

- **재시작 0.5초 이내.** 패배 연출 없음. 화면이 그대로 초기화되고 손이 바로 다시 움직인다
- 붕괴 0.8초만 스킵 불가다. 즉사가 없는 대신 무너지는 걸 보게 만드는 것이 이 게임의 유일한 강제 대기다

## 검증 훅 (AI 활용 기술 문서 재료)

`window.__game`에 노출:

```
{ heat, cursorSpeed, windowOpenMs, residualCoverage,
  holes: [{ depth, state }], decisionsPerSec, failReason, seed, frame }
```

`scripts/balance-sim.ts` — 고정 시드 + 고정 타임스텝 헤드리스. 같은 입력이면 같은 결과.

**지배 전략 봇으로 깊이를 증명한다.** 이 게임의 유일한 깊이 주장은 "같은 궤적을 재사용할 수 없다"이고, 그 주장은 봇 하나로 참·거짓이 갈린다.

| 봇 | 행동 | 합격 조건 |
|---|---|---|
| `circleBot` | 화면 중앙에 큰 원을 일정 속도로 계속 그리다가, 창이 열리면 최근접 구멍으로 직선 진입 | **클리어율 < 20%.** 이 봇은 궤적을 재사용한다. 40%를 넘으면 `RESIDUAL_DECAY`가 너무 빨라 잔열이 무의미하다는 뜻이고, 그러면 이 게임에 깊이가 없다 |
| `stopBot` | 최소한만 식히고 즉시 정지해 밀어넣음 | 클리어율 ≈ 0%. 넘으면 `HEAT_BASE`가 너무 낮다 |
| `maxSpeedBot` | 항상 최대 속도, 절대 정지 안 함 | 클리어율 0%. 창은 계속 열리지만 꽂을 수 없어야 한다 |
| `greedyBot` | 매 프레임 잔열이 가장 낮은 방향으로 이동(탐욕적 최적화) | 클리어율 < 60%. 이 봇이 사람보다 잘하면 "새 궤적 찾기"가 계산 문제일 뿐 손 문제가 아니다 |
| `humanReplay` | 녹화한 사람 입력 재생 | 클리어율 > 60% |

**깊이 증명 = `circleBot` < 20% AND `humanReplay` > 60%가 동시에 성립.** 하나만으로는 아무것도 증명하지 못한다.

추가 측정:
- **입력 미화 효과** — 원본 마우스 경로와 2차 시스템 출력 경로의 저크(가속도 변화율) 총량 비교. 몇 배 줄었는지를 숫자로 낸다
- **결정 밀도** — `decisionsPerSec`가 3~5 구간에 들어오는지. 초당 3 미만이면 코어 루프 주장이 거짓이다

## 범위 밖

- **막대 종류, 구멍 종류, 콤보 배수, 점수 숫자** — 판정 축이 하나(온도 대 정지)여서 성립하는 게임이다. 축을 늘리면 30초 안에 안 읽힌다
- **래그돌 물리 · 실시간 용융 시뮬레이션** — 붕괴는 결정론 연출이다. 확률에 걸지 않는다
- **카메라 이동, 씬 전환** — 최종 화면 하나를 뺀 전부가 한 화면 안이다
- **화면을 덮는 파티클** — 불꽃은 막대 끝 주변 소량만. 구멍과 막대를 가리는 순간 주스 과잉이 된다
- **세이브, 랭킹, 절차 생성 레벨, 네트워크**
- **3D, 스프라이트, 외부 이미지·오디오·폰트 파일**
