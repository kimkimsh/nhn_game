# 한꺼번에 켜기 — 간이 기능 명세

> 고도화 전 단계의 골격만. 수치는 전부 튜닝 대상이다.

## 화면 구성

한 화면 고정. 성냥 다섯 자루가 **화면 높이의 40~60%** 크기로 세워져 있다.

```
┌──────────────────────────────────────────┐
│              [ 3 / 5 ]                   │
│                                          │
│   ▲     ▲     ▲     ▲     ▲             │
│   ═     ═  ←  발화 문턱선 (성냥마다 개별) │
│   ●     ●     ●     ○     ○  ← 머리      │
│   │     │     │     │     │  ← 막대      │
│   │     │     │     │     │              │
│  ···   ·     ····   ·    ··  ← 가루      │
└──────────────────────────────────────────┘
```

**물체를 크게 만드는 것이 필수다.** 머리 지름이 왕복 이동거리와 같은 급이어야 왕복이 왕복으로 보인다. 작으면 이 게임의 코어 동사가 영상에 안 찍힌다.

- **머리**: 원. 회색 → 주황으로 색 보간 (= 온도)
- **문턱선**: 머리 위를 가로지르는 짧은 가로선. 그을음이 앉을 때마다 눈에 보이게 **위로 밀려 올라간다**
- **불**: 색이 아니라 **형태**로 구분한다. 머리 위로 삼각형 불꽃이 튀어나온다
- **막대**: 세로선. 왕복 N회마다 **뚝 한 칸(막대 길이의 1/8) 짧아지고** 가루 덩어리가 한 번에 떨어진다. 연속 축소는 영상에서 존재하지 않는 것과 같다

## 입력

| 입력 | 동작 |
|---|---|
| 마우스 버튼 누른 채 좌우 이동 | 커서 아래 성냥을 비빈다. 왕복 속도가 곧 입열량 |
| 버튼 뗀 채 이동 | 이동만. 비비지 않음 |
| 아무 키 | 실패 후 즉시 재시작 |

요구 왕복 주파수는 **4~5Hz**로 낮게 잡는다. 손목 부담이 정밀도를 갉아먹으면 오래 할수록 게임이 나빠진다.

## 상태와 판정

성냥 하나의 상태는 정수/실수 다섯 개로 완전히 기술된다.

| 변수 | 의미 |
|---|---|
| `temp` | 현재 온도. 비비면 오르고, 손이 떠나면 지수 감쇠 |
| `threshold` | 발화 문턱. 화면의 가로선. 그을음이 앉을 때마다 상승 |
| `length` | 남은 막대 길이. 0이면 그 성냥은 영영 못 켠다 |
| `state` | `COLD` / `HEATING` / `LIT` / `BURNT_OUT` / `DEAD` |
| `burnLeft` | `LIT` 상태에서 남은 연소 시간 (2~3초) |

**전이 규칙**

```
temp ≥ threshold              →  LIT,  burnLeft = BURN_WINDOW
LIT 상태로 burnLeft 소진      →  BURNT_OUT (영구)
발화점 바로 아래 체류 누적    →  threshold 상승 (그을음), 선이 위로 밀림
이웃이 LIT + 거리 < R         →  복사열로 temp 상승 → 혼자 붙을 수 있음
length ≤ 0                    →  DEAD (그 판은 그 시점에 끝)
```

**승리 판정**: 다섯 개가 **동시에 LIT**. 즉 첫 발화의 `burnLeft`가 남아 있는 동안 다섯 번째가 붙어야 한다.

> 초기 안의 "같은 프레임에 다섯"은 냉각 0.5초 + 커서 이동 0.15~0.3초 아래에서 산술적으로 도달 불가능하다. 연소 창이 그 구멍을 메운다.

## 파라미터 (튜닝 대상 — 헤드리스 스윕 축)

| 이름 | 의미 | 폐기 기준과의 관계 |
|---|---|---|
| `COOL_TAU` (τ) | 냉각 시상수 | **1차 관문의 스윕 축 1** |
| `WEAR_PER_STROKE` (w) | 스트로크당 마모 | **1차 관문의 스윕 축 2 / 2차 관문의 대상** |
| `BURN_WINDOW` | 연소 창 | 2~3초 |
| `SOOT_RATE` | 문턱 상승 속도 | 지배 전략 방어의 핵심 |
| `RADIANT_R` | 복사열 반경 | 이웃 자동 발화 |
| `HEAT_PER_STROKE` | 왕복당 입열 | 요구 주파수와 연동 |

τ와 w 두 축의 격자 스윕이 이 게임의 밸런스 증명 전부다.

## 콘텐츠 분량

- 스테이지 **6개**. 성냥 배치와 파라미터만 다르다
- 1판 15~25초, 전체 완주 3분 이내
- 진행: 3자루 → 5자루 → 간격 좁음(복사열) → 마모 심함 → 문턱 편차 큼 → 종합

레벨 셀렉트 필수.

## 오디오 (Web Audio 절차 생성)

| 사건 | 소리 |
|---|---|
| 비빔 | 대역 필터 노이즈. **왕복 속도가 그대로 음정** |
| 문턱 근접 | 배음이 하나 올라옴 |
| 발화 | 짧은 노이즈 버스트 + 반음 상승. 몇 번째냐에 따라 음이 올라감 |
| 꺼짐 | 반음 하강 |
| 막대 마모 한 칸 | 탁 (짧은 클릭) |

**무음으로도 전부 이해된다.** 왕복 속도는 빗금 다발 눕는 방향으로, 온도는 색으로, 문턱은 선으로 중복 표현된다.

## 승패와 흐름

```
타이틀 → 스테이지 선택 → 플레이 → (승리 | 패배) → 즉시 재시작
                                        ↓
                              연출 없이 0.3초 만에 재배치
```

- 승리 연출: **0.6~0.8초 슬로우 + 화면 전체 플래시.** 규칙상 판정은 그대로 두고 연출만 늘린다. 게임 최대의 보상이 영상에서 가장 짧으면 안 된다
- 실패 화면에 남는 것: 막대 길이와 가루 더미. **그 자체가 성적표다**

## 검증 훅 (AI 활용 기술 문서 재료)

- `window.__game`에 `{ temps[], thresholds[], lengths[], states[], strokeCount }` 노출
- `scripts/balance-sim.ts`
  - **τ × w 격자 스윕** → 클리어율 히트맵 JSON. 20~80% 칸 비율이 10% 미만이면 CI 실패
  - **라운드로빈 봇** (다섯을 순서대로 균등하게 비비는 단순 정책) 클리어율
  - **몰아치기 봇** (하나씩 문턱까지 채우는 정책) 클리어율
  - 두 봇의 클리어율 차이가 0에 가까우면 "전략이 존재하지 않는다"는 뜻
- 결정론: 난수 0. 같은 입력 시퀀스 → 같은 결과
