# 머릿수 — 간이 기능 명세

> 고도화 전 단계의 골격만. 수치는 전부 튜닝 대상이다.

## 화면 구성

한 화면 고정. 탑다운.

```
┌──────────────────────────────────────────┐
│  ▣ ▣ ▣ ▣ ▣ ▢  ← 덩어리 카운터 (숫자 아님)  │
│                  6번째 칸이 켜지면 빨강     │
│  ┌────────────────────────────────┐      │
│  │   ◯      ◗●     ← 나(안쪽 점)  │      │
│  │        ◯                       │      │
│  │   ◯         ◯  ← 자율 배회      │      │
│  │                          [문]  │      │
│  └────────────────────────────────┘      │
│  [다음 판정까지 남은 시간 — 가로 게이지]   │
└──────────────────────────────────────────┘
```

- **카운터**: 숫자가 아니라 **방을 축소한 실루엣 칸**. 매 프레임 검출된 덩어리를 그대로 축소해 그린다. 정지 화면 한 장에서 "칸 다섯인데 덩어리 여섯"이 읽혀야 한다
- **플레이어**: 겹쳤을 때 host 도형 색으로 0.15초 만에 물들고, union 외곽선이 한 겹으로 다시 그려진다. 위치는 **윤곽에 기여하지 않는 안쪽 점 하나**로만 표시 — 주인공을 눈으로 따라갈 수 있으면서 "우리는 한 덩어리"도 지켜진다
- **침식 반경**: 각 도형 테두리에 반투명 링. "얼마나 겹쳐야 한 덩어리인가"를 목격시킨다
- **판정 게이지**: 다음 판정까지 남은 시간. **값을 숨기면 실패 귀속이 무너진다**

## 입력

| 입력 | 동작 |
|---|---|
| 방향키 또는 WASD | 플레이어 이동 (아날로그, 격자 아님) |
| 아무 키 | 실패 후 즉시 재시작 |

**격자는 폐기한다.** 아날로그 이동이라야 소코반 오독이 죽는다.

## 판정 — 이미지 연산

```
1. 방을 흑백 마스크로 렌더 (플레이어 + 도형 전부 = 흰색)
2. 침식(erosion) 1단계 — 테두리를 반지름 r만큼 깎는다
3. 연결 요소(connected components) 개수를 센다
4. 그 개수가 TARGET과 다르면 즉시 실패
```

**침식이 이 게임의 핵심 부품이다.** 없으면 최적 플레이가 "겹치기"가 아니라 "1픽셀 스치기"가 되고, 그러면 플레이어는 방을 안 보고 상단 카운터만 보게 된다.

**판정 연출**: 훑는 선이 아니라 **방 전체가 한 프레임 번쩍이는 플래시.** 전역 스냅샷 판정을 유지하면서 연출과 규칙을 일치시킨다. (훑는 선을 쓰면 플레이어가 "선이 지나간 쪽은 풀어도 되겠지"라는 잘못된 모델을 만들고 그 모델로 죽는다.)

**정답 보상**: 판정 통과 시 합쳐진 덩어리 윤곽을 따라 **0.2초짜리 초록 테두리**가 그려진다. 정답 플레이가 1.5초마다 눈에 보이는 사건이 되고, 동시에 "판정 대상은 윤곽"을 글자 없이 가르친다.

**실패 프레임**: 0.4초 정지 + 여섯 개 윤곽 전부 표시 + 문제의 두 도형에 링. 이게 없으면 판정선에서 먼 죽음이 "선이 어떻게 나를 잡았지?"로 오귀인된다.

## 도형 규칙

| 종류 | 개수 | 동작 |
|---|---|---|
| 고정 도형 | 2~3 | 움직이지 않음 |
| **자율 배회 도형** | **2~3** | 스스로 천천히 떠다님. **플레이어에게 절대 밀리지 않는다** |

**밀기(push)는 절대 넣지 않는다.** 넣는 순간 소코반이 되고, 동시에 지배 전략("붙어서 대기")이 부활한다.

자율 배회가 만드는 것: 매 판정마다 방의 기준 덩어리 수가 5와 4 사이에서 흔들린다. NPC 둘이 자기들끼리 붙는 순간 **플레이어는 개활지에 혼자 서 있어야 한다.**

## 파라미터 (튜닝 대상)

| 이름 | 초기값 후보 | 의미 |
|---|---|---|
| `TARGET_COUNT` | 5 | 유지해야 할 덩어리 수 |
| `EROSION_R` | — | 침식 반경. **"확실한 겹침"의 정의** |
| `SCAN_INTERVAL` | 1.0~2.2초 사이 흔들림 | 고정 1.5초는 3판이면 몸에 새겨져 정보값이 0이 된다 |
| `WANDER_SPEED` | — | 배회 속도 |
| `PLAYER_SPEED` | — | 판정 사이에 몇 걸음 갈 수 있는가 |

## 콘텐츠 분량

- 스테이지 **6개**
- 1판 20~40초, 전체 완주 3~4분
- **1스테이지는 반드시 "두 도형이 딱 붙어 있는 배치"로 시작한다.** 플레이어가 그 큰 덩어리에 뛰어들면 4가 되어 즉사시킨다. **"잘 숨었는데 죽었다"를 첫 30초에 박는 것이 이 게임의 튜토리얼 전부다**
- 진행: 고정 도형만 → 배회 1개 → 배회 2개 → NPC 합체 발생 → 문 앞 강제 노출 → 종합

레벨 셀렉트 필수.

## 오디오 (Web Audio 절차 생성)

| 사건 | 소리 |
|---|---|
| 판정 임박 | 짧은 틱, 간격이 좁아짐 |
| 판정 통과 | 낮은 사인 하나 |
| 덩어리 수 변화 | 개수만큼 음정 이동 (5→6은 위, 5→4는 아래) |
| 실패 | 짧은 노이즈 + 즉시 컷 |

**무음으로도 전부 이해된다.** 개수는 카운터 칸으로, 판정 타이밍은 게이지로 보인다.

## 승패와 흐름

```
타이틀 → 스테이지 선택 → 플레이 → (승리 | 패배) → 즉시 재시작
                                        ↓
                          같은 배치로 0.3초 만에 재시작
```

- 승리: 문 도달. **문은 겹친 상태로 못 연다** — 마지막 한 번은 반드시 홀로 서야 한다
- 패배: 판정 시점 덩어리 수 불일치

## 검증 훅 (AI 활용 기술 문서 재료)

- `window.__game`에 `{ blobCount, target, erosionR, playerBlobId, scanCount, soloScans }` 노출
- `scripts/balance-sim.ts`
  - **붙어서 대기 봇** (전부 한 덩어리로 붙여놓고 문까지 직진) 클리어율 → **폐기 기준 1의 대상. 60% 초과면 CI 실패**
  - **개수 계산 봇** (매 판정마다 목표 개수를 만족하는 위치로 이동) 클리어율
  - 두 봇 차이가 없으면 이 게임에 손이 할 일이 없다
  - `soloScans` (개활지에 혼자 선 채 통과한 판정 횟수) — 15판 중 3회 이하면 규칙이 작동하지 않는다는 뜻
- 결정론: 고정 시드. 배회 도형 경로까지 시드에서 나온다
- **밸런스 증명 방식이 나머지 넷과 다르다** — 물리 시뮬이 아니라 이미지 연산이라 상태가 정수 하나(연결 요소 개수)로 떨어진다. 너비우선탐색으로 "이 배치에 해가 존재하는가"를 근사가 아니라 **탐색으로 증명**할 수 있다

## 범위 밖

- 밀기(push) — 넣는 순간 소코반이 되고 지배 전략이 부활한다
- 격자 이동 — 소코반 오독의 절반이 여기서 나온다
- 시야 콘, 경비 AI, 소음 시스템 (전부 이 게임이 삭제한 것들)
- "루프"라는 단어 (홍보 문구 포함)
- 세이브, 랭킹, 절차 생성, 네트워크
- 스프라이트, 외부 이미지·오디오 파일
